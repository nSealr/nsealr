## Recommended minimum

Use the existing synchronous Rust authorization API in a new, explicitly opt-in
public-fixture driver with separate supervision of compute, draw and human wait.
Keep one `AuthorizationSession` for the operation. Keep each `review_step` call
and its local presentation callback alive until that presentation receives its
fresh local gesture, rejection, cancellation or expiry. A supervisor remains
active throughout that callback. This is an ordinary synchronous call with
valid Rust borrows, not suspension or asynchronous reuse of a returned callback.

This recommendation differs from proposal `00c46dfe`: a new split core API is
one concrete alternative, but its necessity has not been established. The
existing trait explicitly permits awaiting or polling a fresh event for the exact
frame. HRT-C01 at `455d8e5a` establishes typechecked owned representation only;
this recommendation does not import its example or treat it as runtime evidence.

The decision to be reviewed is the new driver and supervisory timing contract.
Neither the current C ABI nor the old C5000 helper becomes interactive by a flag,
a timer override, or a saved approval. The old native path and its gates stay
exactly as they are. The [implementation admission brief](admission-brief-2026-10-25.md)
fixes the proposed first scope and discriminating acceptance. This amendment
addresses HRT-DESIGN-01/02 from the distinct review of `27ddd70d`; that candidate
remains preserved. A is viable in principle. The first canary is deliberately
limited to two host actors and one private result, without client publication.

## Two concrete solutions

| Property | A Existing synchronous API and supervised callback | B New split core transition API |
| --- | --- | --- |
| Engine owner | One Rust owner lives through the operation. | Same owned state, with private pending presentation state added. |
| Human wait | Inside the same `present` call, after complete draw; an independent supervisor watches real expiry/cancel and owns result eligibility. | Between `prepare_frame`, complete-draw commit and `accept_local_event`; no callback/borrow is live while waiting. These are proposed APIs, not existing methods. |
| Input binding | One invocation, exact frame, draw epoch and fresh complete gesture; only its return can advance the core. No action survives a returned `None`. | New unforgeable internal pending epoch and draw-commit state bind the later fresh gesture; public epochs alone grant no approval. |
| Required changes | New fixture driver and strict local supervisory protocol. No core or C ABI change is initially required. | Core state machine, new public contracts, invalidation and concurrency rules, catalog/policy version decisions, plus a new provider. |
| Main risk | Callback or device IO can block; supervision must remain independent and must never classify draw/compute as human idle. | Extra transitions can introduce stale-frame/duplicate-input authority or consent reuse; considerably larger affected review perimeter. |
| When to choose | First bounded host demonstration and a device adapter whose local IO can be independently supervised. | A real integration requires no live callback/borrow during wait, or A cannot meet measured cancellation/IO/ownership requirements without transferring a cached action. |

Recommend A for the next scope. It directly honors the current trait rather than
inventing a resume operation. B is a finite fallback under the stated trigger;
it is not an automatic prerequisite or APIv2 selection. An actor/protocol version
for A does not change numeric signing wire version 2 or the internal authorization
v1 domain.

## Timing decision

Existing O8/shared cleanup4, native C5000, fixture client100ms, core100 ticks and
service deadline intersections are different clocks. None is a universal human
policy. Leave every existing path and threshold unchanged.

For the proposed standalone public-fixture driver, use the existing core lifetime
of 100 ticks and the already specified engineering conversion of one real elapsed
second per tick, from one fixed monotonic origin. It is a maximum for the experiment,
not a selected Pi/S3/P4 product duration. The supervisor derives the exact absolute
core tick-boundary expiry, also checks an explicit caller deadline when present,
and uses the earlier boundary. Draw, Next, Back, polling, None and reconnection
cannot extend it. A missing/rolled-back/overflowed clock revokes eligibility.

The supervisor alone owns phase transitions and the remaining active ledger.
The first host canary uses two actors, supervisor S and single-process Rust owner R,
one direct original 259-byte input and one 5500ms passive interval. S owns the synthetic
cell sink and independently observes every completed draw command and commit;
R's COMMIT/WAIT labels cannot exempt time. Before any exemption S verifies the
exact incarnation/invocation/epoch/sequence, complete frame and its own sink receipt,
records OS CPU baselines, then sends `WAIT_ACK`. R remains inside the same callback.
On a fresh local cycle S first exits HumanWait, charges waiting CPU and arms the
remaining active budget, then sends `RESUME_ACK` with the scoped cycle. Only that
acknowledgement permits R to return input or enter core/provider/encoder work.

The aggregate ceiling remains 5000ms, charged from real monotonic active wall
intervals plus conservative CPU upper bounds for S and R during the one exempt
wait. It includes startup, request/catalog work, all draw, core/auxiliary/signing,
encoding, private staging and bounded parent protocol handling through known
settlement/private-result retention. Parent and child active work share the same
wall interval; overlapping intervals do not mint separate budgets. No resume
replenishes it. Wait CPU subcaps are R 100ms and S 400ms, both deducted from those
same 5000ms rather than added to them. Independent `/proc/<pid>/stat` process CPU
counters constrain a false WAIT; the source-admitted canary requires Linux
`SC_CLK_TCK=100`, includes quantization conservatively and forbids descendants.
This observation bounds charged process work; it does not identify a private
backend call or prove completion of blocked IO. S's own sink receipt supplies the
separate complete-draw observation. No physical draw driver is admitted here.

S polls at most 25ms and must observe monotonic checkpoints no more than 50ms apart;
records and handling are capped as specified in the brief. A gap over 50ms, including
a pause/deschedule, accounting failure or any exceeded cap revokes eligibility
before S processes an input/resume/result. These are admission/failure thresholds,
not an OS scheduling guarantee. While S is stopped it cannot guarantee a kill or
CPU ceiling by that wall instant. R has no valid resume without S's ACK; late
results remain private and a failed gap cannot become a passing run on resumption.
The legacy C5000 clock is never paused, renamed or reused.

A full cryptographic verifier could monopolize a two-actor supervisor. Therefore
the minimum canary retains a private response only after exact settlement and
runs the existing independent oracle afterward, outside its eligibility protocol.
It qualifies neither a live client dispatch nor a publication deadline. A future
public release path must charge verifier/parent/currentness/publication work to
the same remaining ledger, keep expiry/cancel monitoring responsive with a separately
watched verifier or an admitted bounded incremental verifier, and obtain separate
source admission. A preemptible clock-check-plus-write cannot be called an atomic
wall-deadline guarantee. This requirement is left explicit rather than inventing
an additional actor in the first canary.

The new executable can observe its `sign_approved` entry count and its injected
`AuxiliarySource` call count. It cannot observe private backend attempts or inject
a private backend failure through the retained public API. Source-identical K01
core proofs retain their original run identities; post-core response mutations
are independent-verifier negatives. No new backend seam or backend counter is
required. The brief partitions these evidence roles.

## Decision limits

A is not admitted for runtime or implementation by this document. Root must
review the frozen brief and the eventual literal source/record grammar/watchdog
placement before launch. Connected operation additionally needs actual client
compatibility; its present shorter deadline remains authoritative. A successful
standalone delay cannot qualify an expired client request or an automatic retry.

Production custody, entropy, physical readable glyphs/buttons/touch, camera,
ARMv6/image/loader, Pi/P4/S3 hardware, no-secret-persistence and device release
remain their existing gates. The fixture identity is the already-public test key
11x32, with expected public key `4f355bdc...5871aa`. No production key, default
route, S04 reopening, custom-board work or canary import belongs to this scope.
